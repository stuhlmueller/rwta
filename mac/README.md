# Real World Text Adventure — native macOS app

A native SwiftUI macOS frontend for the rwta game. It reuses the existing
Python game engine (LLM, web search, location, save/load) by spawning it as a
subprocess and talking JSON-RPC over stdin/stdout, and adds two visual
panels alongside the chat:

- **MapKit** view tracking the player's current location in real time.
- **Scene image** generated by the OpenAI Images API (`gpt-image-2`) after
  every narrator turn, using a saved visual continuity ledger so recurring
  people, places, items, clothing, and spatial layouts do not drift. Images
  default to photorealistic style and can be rerendered in alternate styles
  like Classic Adventure, Cinematic Painterly, Watercolor, Noir Comic, and
  Pixel Art.

No webviews, no Electron — pure AppKit/SwiftUI plus MapKit.

## Why MapKit instead of Google Maps?

Google does not ship a native macOS Maps SDK; their non-webview options are
limited to the [Static Maps API](https://developers.google.com/maps/documentation/maps-static)
(which is just a PNG, no panning/zooming) or embedding the JS API in a
WKWebView. MapKit is Apple's first-class native map framework, supports
3D/realistic elevation, and requires no API key — so it is the right pick
for a no-webview macOS app.

If you really want Google tiles, set `RWTA_MAP_PROVIDER=google_static` in a
future iteration and wire up a static-image overlay; MapKit's
`MKTileOverlay` can also be pointed at custom tile servers, though
non-Google tile providers (OpenStreetMap, Mapbox) are simpler to use and
have clearer terms.

## Requirements

- macOS 14 (Sonoma) or newer
- Swift 5.9+ (Xcode command-line tools or full Xcode)
- Python 3.11+ with `uv` installed (`brew install uv`) **or** an activated
  `.venv` inside the rwta repo
- `ANTHROPIC_API_KEY` — required for the narrator
- `OPENAI_API_KEY` — optional; without it scene illustrations are skipped

## Run

From the rwta repo root:

```bash
# install Python deps (only needed once or after pulling)
uv sync

# build + launch the Swift app
mac/run.sh
```

For a release build:

```bash
BUILD=release mac/run.sh
```

To use the cheaper Sonnet model for narration, set `RWTA_FAST=1` (the GUI
respects the same env vars as the CLI).

## How it works

```
┌────────────────────────┐  newline-delimited JSON   ┌────────────────────────┐
│ SwiftUI app (RWTA.app) │ ◀─────── stdout ──────── │ Python rwta.gui_server │
│  - HSplitView layout   │ ───────  stdin  ──────▶ │  - GameNarrator        │
│  - ChatPanel           │                          │  - GameState           │
│  - MapPanel (MapKit)   │                          │  - tools / web search  │
│  - ScenePanel (style + │                          │  - imagegen/cache      │
│    cached history)     │                          │    (OpenAI)            │
└────────────────────────┘                          └────────────────────────┘
```

- `BackendBridge.swift` spawns `python -m rwta.gui_server` (via `uv run` or
  the project venv), reads its stdout line-by-line, and exposes a typed
  request/response API plus an event stream.
- `GameViewModel.swift` is the single source of truth for the UI; events
  from the backend mutate `@Published` properties on the main actor.
- `rwta/gui_server.py` wraps the existing `GameNarrator`/`GameState` and
  emits structured events instead of writing to the terminal.
- `GameNarrator.update_visual_continuity` maintains a compact visual bible
  in `GameState.visual_continuity` after each narrator turn. It is persisted
  in save files and rebuilt after regeneration to avoid stale visual facts.
- `rwta/imagegen.py` renders the most recent narrative scene with
  `gpt-image-2` (low quality, 1536×1024 landscape), prepends the visual
  continuity ledger as high-priority prompt context, and ships a base64 PNG
  back over the wire. The backend also writes each PNG to
  `~/.rwta/images/<save-name>/` and persists metadata in `image_history`, so
  loading a save reuses cached images instead of rerendering.
- The Swift scene panel exposes the image style selector and lets you page
  through the previous cached images for the current run. The start menu uses
  each save's latest cached render as a preview thumbnail.
- If the narrator fails or returns an empty response, the chat panel shows a
  retry button that replays the failed turn through `RWTA_FALLBACK_MODEL`
  (default `gpt-5.5`) so the run can recover without restarting.

## Keybindings

| Shortcut | Action |
|----------|--------|
| `Return` | Submit the typed action |
| `⌘1` / `⌘2` / `⌘3` | Pick the corresponding suggestion |
| `⌘L` | Look around (re-describe surroundings) |
| `⌘R` | Regenerate the last narrator response |
| `⌘S` | Save the current game |

## Env vars (rwta.gui_server respects all the CLI vars)

| Var | Default | Notes |
|-----|---------|-------|
| `ANTHROPIC_API_KEY` | — | required |
| `OPENAI_API_KEY` | — | required for scene images |
| `RWTA_PROJECT_DIR` | auto-detected | path to the rwta repo (only needed when running from a relocated app bundle) |
| `RWTA_PYTHON_CMD` | `uv run` | override the interpreter command |
| `RWTA_IMAGE_MODEL` | `gpt-image-2` | OpenAI image model |
| `RWTA_IMAGE_SIZE` | `1536x1024` | one of `1024x1024`, `1536x1024`, `1024x1536`, `auto` |
| `RWTA_IMAGE_QUALITY` | `low` | `low`, `medium`, `high`, `auto` |
| `RWTA_IMAGE_STYLE_ID` | `photo` | default image style (`photo`, `monkey_island`, `cinematic_painterly`, `watercolor`, `noir_comic`, `pixel_art`) |
| `RWTA_TIMEZONE` | `America/Los_Angeles` | in-game clock |
| `RWTA_PRIMARY_MODEL` | `claude-opus-4-7` | narrator model |
| `RWTA_FAST_MODEL` | `claude-sonnet-4-6` | loading-message model |
| `RWTA_FALLBACK_MODEL` | `gpt-5.5` | OpenAI fallback model used by the retry button after narrator failures |
| `RWTA_LOG_LEVEL` | `WARNING` | logged on stderr |
| `RWTA_VISUAL_CONTINUITY_MAX_CHARS` | `1400` | maximum length of the saved image consistency ledger |
| `RWTA_VISUAL_TRANSCRIPT_MAX_CHARS` | `9000` | transcript budget used when rebuilding the visual continuity ledger |

Save files live in `~/.rwta/saves/` and cached scene images live in
`~/.rwta/images/`. Saves remain fully shared with the CLI.

## Limitations

- The Swift app is built via plain SwiftPM, so it currently runs as a
  loose executable rather than a `.app` bundle. Launching from Finder or
  the Dock is not yet supported; use `mac/run.sh`. A bundle target can be
  added later (xcodegen, `.xcodeproj`, or hand-rolled).
- Image generation is not streamed — each scene appears once OpenAI returns
  the full PNG (~5–15s for `low` quality on `gpt-image-2`).
- The map shows your current location only; intermediate routes between
  locations are not drawn. (`update_location` events from the LLM advance
  the pin.)
